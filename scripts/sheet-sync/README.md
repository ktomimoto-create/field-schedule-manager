# 行動予定表の自動取り込み（Google Apps Script・PC 不要）

Google ドライブ「1．行動予定表/YYYY年/M月/MMDD」のスプレッドシートを読み、本番の予定（schedules）へ送る。
今日と明日のシートを 5 分ごと（夜 20 時〜翌 7 時は 15 分ごと）。シートは読むだけで書き換えない。
設計は `docs/sheet-sync-design.md`。

## 0. 先に DB（富本さん）

Supabase の SQL Editor で `sql/sheet_sync.sql` を丸ごと実行する（表 3 つと関数。既存の表は変えない）。

## 1. Apps Script を用意する（上田さん）

1. 行動予定表を読めるアカウントで https://script.google.com を開き「新しいプロジェクト」（名前は「予定管理 行動予定表の取り込み」など）
2. `sheet-sync.gs` の中身を貼り付けて保存
3. 関数 `setup` を選んで実行 → 権限を許可（ドライブ・スプレッドシートの閲覧、外部への接続）
4. 実行ログに出る SQL（`insert into public.fsm_ingest_tokens …`）を、富本さんに SQL Editor で実行してもらう

## 2. 10 月分を「試し」で流す（DB は変わらない）

関数 `dryRunOctober` を実行 → 実行ログに日ごとの件数が出る。

| 列 | 意味 |
|---|---|
| 行数 | シートの予定の行 ＋ 1 行目の休暇・社内予定の人数 |
| 追加 | 本番に新しく入る予定 |
| 結び付け | すでに本番にある予定（手で取り込んだもの）と同じと判断して、二重にせず結び付ける |
| 更新 / 変わらず / 食い違い | 2 回目以降の取り込みで使う（初回はほぼ 0） |
| キャンセル | シートから消えたのでキャンセルにする予定（初回は 0） |

最後に「名簿で見つからなかった名前」が出る。外注の会社名（ソシオ・トーヨー等）や「ビル」などは、名前の文字だけで入る。

## 3. 本番に入れて、定期実行を始める

1. 試しの件数を確かめてから `backfillOctober` を実行（10 月分が本番に入る）
2. `startSchedule` を実行（以後 5 分ごとに今日と明日を取り込む）
3. 止めるときは `stopSchedule`

## 注意

- 自動を始めたら、行動予定表の「スプレッドシートから貼り付け」での手での取り込みはやめる（運用している人と合意してから始める）
- 取り込みの記録は DB の `fsm_sync_runs`（試しも残る）。失敗したときは `error` に理由が入る
